# Live operations presentation event contract

Sprint 13 adds a browser-safe presentation stream for the fixed canonical demo. The append-only SQLite ledger remains the evidence authority. Presentation events are generated by code-owned templates immediately around real operations, persisted under ignored `demo/output/<session_id>/events.jsonl`, and replayed through Server-Sent Events.

## Transport

- `POST /api/demo-runs` accepts no body or `{"confirmation":"start-contained-demo"}` and returns HTTP 202 with a server-generated session ID.
- Only one live run may be active; another start returns HTTP 409.
- `GET /api/demo-runs/<session_id>` returns safe presentation status only.
- `GET /api/demo-runs/<session_id>/events` returns `text/event-stream` with each presentation sequence as the SSE `id` and the event object as `data`.
- `Last-Event-ID` replays only later validated events. Duplicate IDs are ignored by the frontend reducer.
- `GET /api/demo-runs/<session_id>/report` serves only the exact generated standalone HTML report after `report.generated` exists.

The Vite development server proxies `/api` to the fixed coordinator at `127.0.0.1:8000`, keeping browser requests same-origin. Neither API accepts a target, host, provider, model, credential, path, prompt, endpoint, or command.

## Exact schema

Every JSONL and SSE event has exactly these fields:

| Field | Rule |
| --- | --- |
| `session_id` | Server-generated `demo:<uuid>` matching the fixed path-safe pattern |
| `sequence` | Zero-based monotonically increasing integer |
| `type` | One stable event name from the list below |
| `timestamp` | UTC ISO 8601 timestamp |
| `stage` | `session`, `preflight`, `mapper`, `authorization`, `verifier_a`, `verifier_b`, `consensus`, or `report` |
| `logical_role` | Fixed logical role or `null`; never a process/service claim |
| `state` | `pending`, `active`, `completed`, `failed`, or `blocked` |
| `headline` | Bounded code-owned template text |
| `explanation` | Bounded code-owned plain-language template text |
| `metadata` | Event-specific allowlisted scalar/list values only |
| `reference` | Optional safe `ledger://`, `scope-controller://`, `verifier://`, `demo://`, or `report://` reference |

The journal rejects unknown fields, unknown event names, disallowed metadata keys, non-UTC timestamps, path traversal, secret-like values, out-of-order replay, partial last lines, appends after a terminal event, and more than 256 events.

## Stable journey

1. `session.started`
2. `preflight.started`, `preflight.completed`
3. `mapper.activated`, `mapper.completed`
4. `identity_reset.started`, `identity_reset.completed`
5. `identity.activated`, `identity.account_b_discovery`, `identity.account_a_retrieval`, `hypothesis.created`, `identity.completed`
6. `verifier_a.activated`, `verifier_a.reset_completed`, `verifier_a.plan_validated`, one or more `verifier_a.call_recorded`, `verifier_a.check_completed`, `verifier_a.completed`
7. The corresponding `verifier_b.*` events, activated only after Verifier A completes
8. `consensus.started`, `consensus.completed`
9. `finding.recorded` only when the ordinary-code verdict is `verified` and a finding was actually persisted
10. `report.started`, `report.generated`
11. `session.completed`

Any incomplete stage instead ends with one `session.failed`. Downstream activation, verdict, finding, and report events are absent. Verifier A and Verifier B are independently planned logical roles with separate resets, but they execute sequentially through Python function calls; the event contract does not claim processes, services, or concurrency.

## Safe metadata

Allowlisted metadata includes route counts; provider/model labels already present in committed configuration; synthetic record IDs and owner labels; HTTP status; reset IDs and logical state hashes; plan hashes and step counts; bounded method/path/account call metadata; body hashes rather than bodies; deterministic boolean results; safe run, hypothesis, and finding IDs; report hashes; and the fixed same-origin report URL.

Events never contain API keys, bearer tokens, environment values, prompts, raw model responses, chain-of-thought, source contents, database contents or paths, authorization headers, arbitrary exceptions, or stack traces. React renders all values as escaped text and never uses `dangerouslySetInnerHTML`.
